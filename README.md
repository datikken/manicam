# Manicam-Servo — двухплатный проект на Arduino Nano

Один репозиторий PlatformIO, **две прошивки** для **двух плат** Arduino Nano
(ATmega328P, 16 МГц). Платы связаны по I2C:

```
   [ ПЛАТА-МАСТЕР ]                          [ ПЛАТА-ВЕДОМЫЙ ]
   джойстик (A0/A1)                         два сервопривода (D9, D10)
   кнопка   (D2)            I2C              светодиод (D4)
   LED связи (D13)  ── SDA(A4) / SCL(A5) ──▶
                    ── GND  / питание   ──
```

Мастер читает джойстик и кнопку и отправляет пакет ведомому.
Ведомый принимает пакет и двигает сервоприводы, кнопка зажигает светодиод.

---

## Структура проекта

```
manicam-servo/
├── platformio.ini          # ОБЩИЕ настройки + два env: servo_board / master_board
├── src/
│   ├── main.cpp            # ВЕДОМЫЙ  (env: servo_board)
│   └── joystick.cpp        # МАСТЕР   (env: master_board)
├── include/
├── lib/
└── test/
```

### Почему два файла в одном `src/`

PlatformIO собирает **всё** содержимое `src/` для **каждого** env. Оба файла
определяют `setup()` / `loop()` (их вызывает `main()` из `framework-arduino-avr`),
поэтому без разделения получились бы дубли символов и ошибка линковки.

Разделение сделано через **`build_src_filter`** — каждый env компилирует
ровно один файл:

| env | собираемый файл | Flash | RAM |
|---|---|---|---|
| `servo_board`  | `src/main.cpp`     | 3812 B (12.4%) | 242 B |
| `master_board` | `src/joystick.cpp` | 3152 B (10.3%) | 241 B |

## Протокол I2C

Пакет **5 байт**, big-endian, адрес ведомого **8**:

| Байт | Поле | Значение |
|------|------|----------|
| 0 | `xH` | старший байт оси X |
| 1 | `xL` | младший байт оси X |
| 2 | `yH` | старший байт оси Y |
| 3 | `yL` | младший байт оси Y |
| 4 | `btn` | 0/1 — кнопка |

- `x`, `y` — диапазон **0..1023** (сырое значение АЦП).
- `btn` — 1 = нажата.
- Ведомый никогда не «тянет» шину: транзакцию завершает мастер.
- Пакет длиной ≠ 5 ведомый **отбрасывает целиком** (гарантия пересинхронизации).

> Контракт задублирован в двух файлах. Меняете формат — меняйте **в обоих**:
> `MSG_SIZE` и порядок полей в `src/main.cpp`, `SLAVE_ADDR`/запись байт в
> `src/joystick.cpp`.

## Распиновка

### Ведомый — `src/main.cpp` (`servo_board`)

| Пин | Назначение |
|-----|------------|
| D9  | Серво №1 (ось X) |
| D10 | Серво №2 (ось Y) |
| D4  | Светодиод |
| A4  | SDA |
| A5  | SCL |

### Мастер — `src/joystick.cpp` (`master_board`)

| Пин | Назначение |
|-----|------------|
| A0  | Джойстик VRx |
| A1  | Джойстик VRy |
| D2  | Кнопка джойстика (`INPUT_PULLUP`, на GND) |
| D13 | LED индикатора связи (на плате) |
| A4  | SDA |
| A5  | SCL |

### Соединение плат

```
GND ─── GND
A4  ─── A4   (SDA)
A5  ─── A5   (SCL)
пит. ── питание
```

> **Не соединяйте вместе два 5 В от USB** — стабилизаторы плат будут
> «бороться» друг с другом. Запитайте одну плату от USB, вторую — от её пина
> **5V**, либо обе от общего источника.

Подтягивающие резисторы I2C (обычно 4.7 кОм на SDA/SCL к 3.3/5 В):
на модулях часто уже стоят; на голых чипах — нужны обязательно.
На короткой шине (в пределах макетки) часто работает и без них.

## Сборка и прошивка

Каждый env прошивается **на свою плату по отдельности**:

```bash
# Плата с сервоприводами
pio run -e servo_board -t upload

# Плата с джойстиком
pio run -e master_board -t upload
```

Сборка без прошивки (проверка компиляции обеих прошивок):

```bash
pio run
```

Монитор порта:

```bash
pio device monitor -b 115200
```

### Порт

PlatformIO сам находит порт (`Auto-detected: COM…`). Уточнить, что висит на COM:

```powershell
pio device list
```

Если порт занят — закройте монитор порта в Arduino IDE/PlatformIO:
открытый монитор держит порт эксклюзивно и даёт `PermissionError(13)`.

---

## Важно: скорость загрузки 115200

В `platformio.ini` жёстко задано:

```ini
upload_speed = 115200
```

Это **вынужденная мера**. Плата — клон на **CH340** с загрузчиком **Optiboot**,
который работает на 115200, а стандартное описание платы `nanoatmega328`
предполагает загрузчик на 57600. Несовпадение даёт ошибку:

```
avrdude: stk500_recv(): programmer is not responding
avrdude: stk500_getsync(): not in sync: resp=0xd0
```

**Если загрузка начнёт сбоить:**
1. Проверьте, что `upload_speed = 115200` не переопределён в env.
2. Нажмите кнопку **Reset** на плате сразу перед `pio run ... -t upload`.
3. Пакет обновлений драйвера CH340 может изменить поведение — перепроверьте.

## Логика мастера (`src/joystick.cpp`)

- **Мёртвая зона ±12** вокруг центра (512) — убирает дрожание серв при
  отпущенном джойстике.
- **Антидребезг кнопки 20 мс** — без внешних библиотек.
- **Отправка только при изменении** — если ничего не поменялось, шина не
  дёргается; первый пакет после старта шлётся всегда.
- **Период 15 мс (~66 Гц)** — согласован с `delay(15)` ведомого.
- **Индикатор связи (D13)** — горит только при `Wire.endTransmission() == 0`
  (ведомый подтвердил). Погас → ведомый не отвечает; пакет будет переслан
  заново при восстановлении связи.

## Логика ведомого (`src/main.cpp`)

- Приём через `Wire.onReceive()`, накопление в `volatile`-переменные,
  запись под запретом прерываний (`cli()`/`SREG`) — атомарный «снимок»
  пары (x, y) без рваных кадров.
- `loop()` раз в 15 мс переводит 0..1023 → 0..180° и обновляет сервы.
- Сервоприводы инициализируются в центр (90°) до первого пакета.

## Технические характеристики

| Параметр | Значение |
|---|---|
| Плата | Arduino Nano, ATmega328P, 16 МГц |
| Платформа | `atmelavr` 5.3.0 |
| Framework | `arduino` (`framework-arduino-avr` 5.4.0) |
| Библиотеки | Wire 1.0.0, Servo 1.3.0 |
| I2C-шина | 100 кГц |
| Частота обновления | ~66 Гц |
| Адрес ведомого | 8 |

Зависимости объявлены явно в `platformio.ini`:

```ini
lib_deps =
    wire
    servo
```

`Wire` поставляется с framework, `Servo` подтягивается менеджером библиотек.
`lib_ldf_mode = deep+` — чтобы зависимости находились по `#include`.

## Известные подводные камни

| Симптом | Причина | Решение |
|---------|---------|---------|
| `stk500 not in sync` | загрузчик 115200 vs 57600 | `upload_speed = 115200` (уже в конфиге) |
| `PermissionError(13)` | порт занят монитором IDE | закрыть монитор порта |
| `undefined reference to 'setup'` | в файле нет `setup()`/`loop()` | добавить точки входа |
| «Nothing to build» | `build_src_filter` не совпал с именем файла | проверить имя в фильтре |
| «More than one package found by servo» | env и библиотека с одинаковым именем | не называть env `servo` |
| Сервы дрожат в покое | шум джойстика у центра | мёртвая зона (`DEADBAND`) |
| Сервы «залипли» на 90° | разделяемые переменные без `volatile` | `volatile` + `cli()`/`SREG` |

## Добавление третьей прошивки

1. Положить файл в `src/`, например `src/third.cpp`, с `setup()` и `loop()`.
2. Добавить env в `platformio.ini`:

```ini
[env:third_board]
build_src_filter = +<third.cpp>
```

3. Прошивать: `pio run -e third_board -t upload`.

Главное — `build_src_filter` должен включать **только** «свой» файл,
иначе в прошивку попадут чужие `setup()`/`loop()` и линковка упадёт.
